# 文档理解 RAG 平台 — 方案设计

## 概述

面向小团队内部使用的 AI 文档阅读助手。用户上传 PDF/Word/Markdown 文档，系统自动解析、存储，生成批判性阅读报告和交互式思维导图，帮助用户快速理解文档内容。

### MVP 范围

- 多格式文档上传（PDF、Word、Markdown）
- AI 生成批判性阅读报告
- AI 生成带标注的交互式思维导图
- 文档管理（上传、列表、删除）

### 不做的事情（MVP 后）

- 自动文档分类
- 数据可视化信息图
- 跨文档对比分析
- 文档问答（Chat with Doc）

### 数据流

**上传链路：**
文件上传 → 格式检测 → 解析器提取文本 → 统一结构化 JSON → 分块 → 嵌入 → 存入 ChromaDB

**生成链路：**
用户选择文档 → 从 ChromaDB 检索关键块 → 组装上下文 → LLM 生成 → 返回前端渲染

## 技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 后端框架 | FastAPI (Python 3.11+) | 异步支持好，生态丰富 |
| 前端框架 | React + TypeScript | 团队通用，生态成熟 |
| PDF 解析 | PyMuPDF (fitz) | 文本提取质量高，支持表格、阅读顺序 |
| Word 解析 | python-docx | 段落+标题层级+表格 |
| Markdown 解析 | Python markdown 库 | 标准解析 |
| 文本分块 | LangChain text-splitters | RecursiveCharacterTextSplitter + 自定义标题增强 |
| 嵌入模型 | 通义千问 text-embedding | 国内直连，中文效果好 |
| 向量数据库 | ChromaDB | 轻量，单机部署，无需额外服务 |
| LLM | 通义千问 / DeepSeek API | 国内直连，支持长上下文 |
| LLM 编排 | 自建 prompt 模板 + API 直调 | 避免引入 LangChain 复杂度 |
| 前端报告渲染 | react-markdown + rehype | Markdown → React 组件 |
| 思维导图 | markmap | 交互式，支持缩放/展开折叠 |
| 文件存储 | 本地文件系统 | 团队内部使用，无需对象存储 |

## 文档处理链路

### 1. 格式解析

三种格式解析为统一的中间 JSON 结构：

```json
{
  "title": "文档标题",
  "sections": [
    {
      "heading": "第一章",
      "level": 1,
      "content": "段落文本...",
      "tables": [{"headers": [], "rows": []}],
      "page": 1
    }
  ],
  "metadata": {
    "filename": "xxx.pdf",
    "format": "pdf",
    "pages": 42,
    "uploaded_at": "2026-07-06T..."
  }
}
```

| 格式 | 解析库 | 提取要点 |
|------|--------|----------|
| PDF | PyMuPDF (fitz) | 文本+表格+页码，保留阅读顺序 |
| Word | python-docx | 段落+标题层级+表格+图片标注 |
| Markdown | markdown + BeautifulSoup | 标题层级+代码块+列表+链接 |

### 2. 分块策略

- **分块方式**：RecursiveCharacterTextSplitter，chunk_size=500 tokens，overlap=50 tokens
- **标题注入**：每块开头附加层级标题路径（如 `# 第三章 > 3.1 背景`）
- **表格处理**：表格单独成块，转 Markdown table 格式（LLM 理解最好）

### 3. 嵌入 & 存储

- 嵌入模型：通义千问 text-embedding-v3（或根据性价比替换）
- 存储：ChromaDB，一个文档对应一个 collection
- 查询时：语义检索 Top-K 相关块，附带标题路径和页码

## LLM 编排 & 提示词设计

两种生成任务共享检索结果，使用不同的 System Prompt。

### 报告生成 Prompt

核心设计理念：**批判性阅读教练**，且自适应分析深度——不是所有文档都值得同等的分析力度。

```
系统角色：
你是一位资深分析师，从业 15 年，以批判性思维和直言不讳著称。
你不会美化任何内容——论证薄弱的你会直接指出，数据缺失的你会明确标注。

## 第零步：文档评估（每次必须先做）
- 文档类型：（学术论文 / 行业报告 / 技术文档 / 其他）
- 篇幅级别：（短篇 ≤5页 / 中篇 5-30页 / 长篇 >30页）
- 信息密度：（高 / 中 / 低）
- 阅读建议：一句话告诉读者应该花多少时间、重点看什么

## 分析策略（根据篇幅自动选择）

### 策略 A：短篇（≤5页）— 全量深度分析
执行完整四步，每一部分做到最详细。

### 策略 B：中篇（5-30页）— 标准分析
执行完整四步，内容拆解按章节归类而非逐段展开。

### 策略 C：长篇（>30页）— 两阶段分析

**第一阶段（本次输出）：**
1. 文档评估 + 结构骨架表格（章节|页码范围|核心内容|重要性1-5★）
2. 全局概览：核心主题、论证主线、关键结论
3. 阅读路径建议（3条：5分钟版 / 掌握核心论证版 / 全面深入版）
4. 结尾引导语："请告诉我你最想深入了解的章节（可多选），我将生成深度分析。"

**第二阶段（用户选择章节后触发）：**
对选中章节执行完整四步分析，每个章节独立输出。

## 四步分析内容（策略 A/B 及策略 C 第二阶段使用）

第一步 — 快速评估：值得花时间读吗？目标读者是谁？
第二步 — 内容拆解：核心主张、论证架构、关键证据[标注出处]、重要数据（表格）、核心概念
第三步 — 批判性分析：最强论据、最弱环节、缺失内容、潜在假设、反方观点
第四步 — 读者指南：精读建议（附页码范围）、可信度评分（论据/逻辑/数据各1-10）、延伸阅读

## 约束
- 每个观点标注原文出处 [参见段落X]
- 文档未提供的信息写明"文档中未提供"，不编造
- Markdown 格式输出，中文为主
```

### 思维导图生成 Prompt

核心设计理念：**不只是层级结构，而是带标注的知识图谱**。

```
系统角色：
你是一位信息架构师，擅长将复杂内容转化为清晰的知识图谱。

生成规则：
- 根节点：一句话概括文档核心主题
- 一层：主要章节/论证模块（5-7个）
- 二层：核心观点/关键概念
- 三层：支撑细节（数据、引用、案例）
- 四层（可选）：值得追问的问题、争议点

节点元标注：
- {bold} — 标记最重要的3个节点，优先阅读
- {warning} — 标记论证薄弱或有争议的节点
- {question} — 标记文档未充分回答的开放问题
- {link:页码} — 标注关键内容在原文的位置
- {concept:解释} — 专业术语的简短通俗解释

约束：
- 总节点数 30-50 个
- 必须覆盖所有主要章节
- 不编造节点
```

### 自适应分析深度

LLM 先评估文档类型、篇幅、信息密度，自动选择分析策略：

- **短篇（≤5页）**：全量深度四步分析
- **中篇（5-30页）**：标准四步分析
- **长篇（>30页）**：两阶段——先出结构骨架+全局概览，用户选择感兴趣章节后再深度分析

### 降级策略

- LLM 调用失败 → 退回到纯规则提取（按标题层级生成基础导图）
- 若报告 prompt 未触发第二阶段（用户未选择章节），长篇文档的结构骨架即为最终输出

### LLM 可配置切换

通过环境变量或前端配置切换模型：
- `QWEN_API_KEY` — 通义千问
- `DEEPSEEK_API_KEY` — DeepSeek

## API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/documents/upload` | 上传文档 |
| GET | `/api/documents` | 文档列表 |
| GET | `/api/documents/{id}` | 文档详情（解析后的结构化内容） |
| DELETE | `/api/documents/{id}` | 删除文档及关联数据 |
| POST | `/api/documents/{id}/report` | 生成/重新生成报告 |
| GET | `/api/documents/{id}/report` | 获取已生成的报告 |
| POST | `/api/documents/{id}/report/deep-dive` | 长文档第二阶段：对选中章节生成深度分析 |
| POST | `/api/documents/{id}/mindmap` | 生成/重新生成思维导图 |
| GET | `/api/documents/{id}/mindmap` | 获取已生成的思维导图 JSON |

## 前端页面结构

```
/                         文档列表页（首页）
/documents/:id            文档详情（上传后查看解析状态）
/documents/:id/report     阅读报告页（Markdown 渲染 + 引用跳转）
/documents/:id/mindmap    思维导图页（markmap 交互式视图）
```

### 报告页设计
- 左侧：Markdown 渲染的阅读报告
- 右上：可信度评分卡片（论据/逻辑/数据 三项）
- 点击 `[参见段落X]` 时，右侧弹出原文段落预览
- 长文档特殊交互：报告顶部渲染章节选择面板，勾选章节后点击"深度分析"触发第二阶段

### 思维导图页设计
- 中央：markmap 渲染的交互式导图
- 节点差异化渲染（bold 加粗高亮、warning 黄色图标、question 问号图标等）
- 点击含 meta 信息的节点弹出详情（原文片段/术语解释/问题）
- 导出按钮：SVG / PNG / JSON

### 通用交互
- 上传后可查看解析进度（状态轮询）
- 报告和导图支持重新生成（用户可修改提示词后重试）
